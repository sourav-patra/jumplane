jumplane

Tell jumplane how big and how risky a task is. It answers with the tool, model, effort and exact command to run, taken from rules you accepted. When a usage limit is close, it answers with the next open lane instead.

Why

Coding agents on a subscription stop when a usage window fills, and the host does not switch for you. Claude Code's model configuration page says rate-limit errors "never trigger a switch" to its fallback model.

Evidence: the phrase "usage limit" appears in 3,575 issues on the Claude Code repository and 1,975 on the Codex repository (GitHub issue search, 3 Nov 2026; the totals include off-topic hits). One of them, claude-code issue 16157, had 727 reactions that day.

jumplane is not a proxy and holds no keys. It reads the limit numbers your tools already show, and it returns a command for you or your agent to run.

Features

  • One screen, jumplane status: each pool, percent used, reset time, age of the reading, holds, and the lane that runs next.
  • jumplane pick maps size, risk and complexity to one of three classes with a published table, then returns the first open lane in your order.
  • A pool at the hold line (90 percent by default) on any window with a valid reading is passed over, and the pick moves to the next lane in the same class.
  • Every lane passed over is listed under skipped with its cause and the command or wait that would open it. An unverified lane is passed over for the next lane in the same class; work never moves to another class.
  • jumplane report records the outcome, tokens and receipt path. Each decision is one line in a plain log file you can read.
  • No proxy, no API keys, no prompt reading, no telemetry. The pick code has no network or process imports. Only the probe used by init and verify imports those modules directly, which a test checks. Python standard library only.
  • Rules and code choose the route, and model output never does.

How it works

Quick start

  1. Install uv, then jumplane from its tag: uv tool install git+https://github.com/sourav-patra/jumplane@v0.1.0. Check: jumplane --version prints 0.1.0.
  2. Run jumplane init. It looks for Claude Code, Codex and a local Ollama server and prints proposed rules without writing them. Check: the answer says "status": "proposed".
  3. Read the rules, then run jumplane init --accept. Check: the answer says "status": "accepted".
  4. Verify each hosted route once, for example jumplane verify codex-standard. This sends one short prompt and uses a little of that plan. Check: "status": "verified".
  5. Run jumplane status. Check: each class shows next and a lane, or a fix: line to run.
  6. Run jumplane pick --size small --risk low --complexity low, launch the returned command, then jumplane report <pick_id> done. Check: the answer says "status": "recorded".

Claude Code shows its limits only through its status line. jumplane init prints the one settings line to add. Without it the Claude pool has no reading and stays unavailable.

It says nothing about quality. init writes one local lane; more local lanes are added by editing the rules file.

No benchmark has run. Setup time for a new user. Behaviour on macOS and Linux (tests ran on Windows only)
  • jumplane is rule based. It does not predict quality.
  • The Codex reader rests on an undocumented log format. Any surprise there means "no reading", and the pool is then unavailable until you record one.
  • The caller states the task shape. A caller can understate it down to the minimum class your rules set.
  • jumplane does not stop two callers from running the same work, and it cannot switch a session that is already running.
  • The event log is a plain file. Anyone with your user account can edit it.
